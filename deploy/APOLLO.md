# Apollo: deployment runbook for christianastrology.org

You are deploying a finished Node.js app to a fresh Ubuntu/Debian VPS. Follow the steps in order. Every step has a check. Don't move on until the check passes. Background detail for any step is in `../DEPLOY.md`.

**Stack:** Namecheap DNS → VPS → Nginx (Let's Encrypt TLS) → Node app (systemd, port 3000, localhost only) → SQLite file. No Cloudflare, no Hostinger, no other proxies or platforms. Don't add any.

## Inputs to collect from the owner first

| Name | Example | Used for |
|---|---|---|
| VPS SSH access (IP, user with sudo) | `203.0.113.10` | everything |
| Owner email (becomes admin) | `owner@…` | `ADMIN_EMAILS`, certbot |
| Stripe secret key | `sk_test_…` first, then `sk_live_…` | memberships + store |
| Printify personal access token | long JWT | store |
| Resend API key | `re_…` | all email |

`PRINTIFY_WEBHOOK_SECRET` is generated by you: `openssl rand -hex 32`.
`STRIPE_WEBHOOK_SECRET` comes from step 5.

## Hard rules

- **Never copy `data/app.db*` from the dev machine.** It contains demo accounts. Production creates its own database.
- Never commit or print `.env` contents in logs or chat. It must be mode `600`, owned by `christ`.
- Don't edit application code on the server. Deploy changes by uploading the project and running `update`.
- Do Stripe in **test mode** (`sk_test_…`) first. Switch to live only after step 8 passes, and live mode needs its own webhook (step 5 again with live keys).

## 1. DNS (Namecheap)

Domain List → christianastrology.org → Advanced DNS. Remove parking/redirect records and any old Hostinger A records. Add:

- `A  @    <VPS IPv4>`
- `A  www  <VPS IPv4>`

Nameservers must be "Namecheap BasicDNS".
**Check:** `dig +short christianastrology.org` and `dig +short www.christianastrology.org` both return the VPS IP.

## 2. Upload the project

From the machine with the code:

```bash
rsync -av --exclude node_modules --exclude .env --exclude .claude --exclude 'data/app.db*' --exclude data/backups ./ USER@VPS:/tmp/christ/
```

**Check:** `ls /tmp/christ/server.js` exists, and `ls /tmp/christ/data/app.db` does **not**.

## 3. Install

```bash
cd /tmp/christ
sudo bash deploy/deploy.sh install --domain christianastrology.org --email OWNER_EMAIL
```

This installs Node 24, Nginx, and certbot. It creates the `christ` user, copies the app to `/var/www/christianastrology`, creates `.env` from the template, and starts the systemd service. It also sets up Nginx, the firewall, the HTTPS certificate (if DNS is ready), and nightly backups.

**Check:** the output ends with the integration check, and
`curl -s https://christianastrology.org/healthz` → `{"ok":true,...}`.
If the certificate step said DNS isn't ready, wait for step 1's check to pass and rerun the same install command.

## 4. Fill in `.env`

```bash
sudo nano /var/www/christianastrology/.env
```

Set: `STRIPE_SECRET_KEY`, `PRINTIFY_API_TOKEN`, `PRINTIFY_WEBHOOK_SECRET` (generated), `SMTP_PASS` (= Resend API key). Leave `SMTP_HOST=smtp.resend.com`, `SMTP_PORT=465`, `SMTP_USER=resend` as they are. Then:

```bash
cd /tmp/christ && sudo bash deploy/deploy.sh update
```

**Check:** the integration check shows ✓ for the Stripe key and the Printify token. It lists Printify shops as `id "title" (sales_channel)`. Put the id of the **API / custom-integration** shop into `PRINTIFY_SHOP_ID` and run `update` again. If no shop has an API sales channel, the owner must create one in Printify (Add new store → API).

## 5. Stripe webhook

Nothing to do in the dashboard: on startup the site creates its own webhook endpoint through the Stripe API (needs `STRIPE_SECRET_KEY` and `APP_URL=https://christianastrology.org`) and stores the signing secret itself. Leave `STRIPE_WEBHOOK_SECRET` blank.
Also in Stripe settings: **Billing → Subscriptions and emails**, turn on Smart Retries and "Send emails about failed payments". Optionally enable Stripe Tax.

**Check:** the service log shows `Stripe webhook ready`.

## 6. Email (Resend) + admin

Resend → Domains → add `christianastrology.org`. Add the DNS records it shows in Namecheap Advanced DNS (Host is only the part before the domain, e.g. `send`, `resend._domainkey`). Click Verify in Resend.

**Check:** the integration check shows "SMTP login works".

Then the owner signs up at `https://christianastrology.org/signup` with `OWNER_EMAIL` and clicks the confirmation email. Admin access requires a confirmed email. If email isn't working yet:

```bash
sudo -u christ bash -c 'cd /var/www/christianastrology && npm run confirm-email -- OWNER_EMAIL'
```

**Check:** the owner sees ⚙ Admin in the header. `/admin` shows Stripe and Printify as "connected".

## 7. Printify + Stripe setup buttons

```bash
sudo -u christ bash -c 'cd /var/www/christianastrology && npm run check -- --setup'
```

This creates the three membership prices in Stripe and registers the Printify webhooks. The same buttons are on `/admin`.

**Check:** the output shows "Membership prices ready" and "Registered 7 webhooks". In Printify, publishing a product makes it appear at `/store` within a minute.

## 8. End-to-end test (Stripe test mode)

Use card `4242 4242 4242 4242`, any future date, any CVC.

1. New account → `/pricing` → join **Devoted** → pay. Back on `/account` it shows Devoted, active. The store shows 20% off, and `/board/welcome/new` opens.
2. `/account` → Manage billing → switch to Saint. The account shows Saint within seconds.
3. Store → add an item → checkout. The order appears in `/admin/orders` as "submitted" and in Printify as an order (On hold unless `PRINTIFY_AUTO_SEND=true`). **Cancel that test order in Printify** so it isn't produced.
4. "Forgot your password?" → the email arrives.
5. A second account replies to a board thread → the first account gets a "New reply" email.
6. `/es` and `/pt` render in Spanish and Portuguese.

When all six pass: put the `sk_live_…` key in `.env`, add a **live-mode** webhook endpoint (step 5) and its secret, run `update`, run `npm run check -- --setup` again (creates live prices), then do one real low-value purchase and refund it from the Stripe dashboard. The refund should email the admin.

## 9. Search engines & AdSense (owner's accounts)

The verification tags, `/ads.txt`, and `/sitemap.xml` are already served. In Google Search Console, Bing Webmaster, and Yandex Webmaster: add the site, choose "HTML meta tag", click Verify, then submit `https://christianastrology.org/sitemap.xml`. In AdSense: add the site, enable Auto ads, and publish the EU consent message (Privacy & messaging).

## Later updates

Upload the new code to `/tmp/christ` (same rsync as step 2), then `sudo bash deploy/deploy.sh update`.
This snapshots the code and database first. If the new version fails its health check, it **rolls back automatically**. Manual rollback: `sudo bash deploy/deploy.sh rollback`. Status: `sudo bash deploy/deploy.sh status`.

## Troubleshooting

| Symptom | Look at |
|---|---|
| Site down / 502 | `journalctl -u christianastrology -n 100 --no-pager` |
| Member paid but no access | Stripe → Webhooks → endpoint → failed deliveries (resend them). Check `STRIPE_WEBHOOK_SECRET` matches *this* endpoint and mode |
| Product published but not on site | `/admin` → "Confirm products stuck in Publishing", then "Refresh store catalog". Check `PRINTIFY_WEBHOOK_SECRET` is set and webhooks are registered |
| Order paid, not in Printify | `/admin/orders` shows the Printify error. Fix it, then click "Retry Printify" |
| No emails | `npm run check`. The Resend domain must be verified, and `SMTP_FROM` must use that domain |
| Certificate errors | `sudo certbot certificates`; DNS must point here; rerun install |

Data lives in `/var/www/christianastrology/data/app.db`. Nightly copies are in `data/backups/` (14 days). Code snapshots are in `/var/backups/christianastrology/`.
